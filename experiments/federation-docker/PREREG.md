- 实验 ID：`federation-docker`
- 日期：2026-11-01
- 状态：**已登记，尚未运行**（本文件先于任何运行提交）
- 性质：**AI 预演 · 本机两个 Docker 容器 · 不是真实多节点**。不计入 M12.6 退出条件（M12.6 要求两台可隔离节点与网络控制）。
- 依据：[开发文档 M12](../../docs/DEVELOPMENT.zh-CN.md) · [ADR-0008](../../docs/adr/0008-federation-sync.zh-CN.md) · [模拟分区登记](../federation-partition/PREREG.md) · [本机 TCP 演示](../federation-tcp/REPORT.md)

## 1. 问题

两个站点运行在**各自的网络命名空间**（两个容器、一个 Docker bridge 网络）中，用**真实的网络断开**（`docker network disconnect`）制造分区。在这种条件下：

1. 分区是否被两端检测到，且分区期间本地写入不受阻？
2. 重连后跨站承诺是否全部可对账，冲突是否全部被报告而不被静默合并？
3. 反复分区与重连是否会让记录或承诺重复增长？

与 [federation-tcp](../federation-tcp/REPORT.md) 的差别：那里是同一台机器上的两个进程、一次性交换，没有分区；这里节点长期运行，周期性重试，分区由网络层制造。

## 2. 设置（先于运行固定）

- 两个容器 `poie-site-a`、`poie-site-b`，同一个用户自定义 bridge 网络 `poie-fed`，每个容器只运行一个 `node` 进程。
- 节点每 250 ms 尝试一次与对端交换：TCP 连接超时 300 ms，读写超时 1 s。交换内容是本站的记录、预留和租约。双方都按 `RecordId` 去重合并记录；预留与租约按（站点, 批次或执行端, 动作或时间窗）去重。
- 编排器通过 `docker exec` 给节点下发"开始写入"信号，并读取节点的状态快照（JSON）。快照写入 `raw/`，判定由 runner 的 `report` 模式从 `raw/` 计算。
- 冲突写入与 federation-tcp 相同：同一幂等键 `shared-key` 的动作、对 `lot-bronze`（可用 5 kg）的预留 4 kg + 3 kg、对 `robot-m1` 的重叠租约；时钟偏差界 2000 ms。

## 3. 场景与期望

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| D0 | 联通基线：两容器启动，尚无写入 | 两端都至少成功交换 1 次；记录 0；冲突 0 |
| D1 | 分区检测：断开 `poie-site-b` 的网络，等待 3 s | 两端在此窗口内交换成功次数不增加，失败次数各至少增加 3 |
| D2 | 分区期间写入：两端各自写入冲突集合，等待 2 s | 两端本地写入成功；各自只看到本站 1 条记录、1 条预留、1 条租约；本地对账 0 冲突（分区隐藏冲突，这是预期） |
| D3 | 重连：恢复 `poie-site-b` 的网络，等待至多 15 s | 两端合并记录 = 2；预留 = 2、租约 = 2（都保留，不删除）；冲突类别恰为 `double_ownership`、`duplicate_idempotency_key`、`over_reservation` |
| D4 | 反复分区/重连 3 轮（每轮断开 2 s、恢复后等待至收敛，至多 15 s） | 每轮结束时记录 = 2、预留 = 2、租约 = 2；冲突类别与条数与 D3 相同 |

## 4. 判定

- 主判定：D0–D4 每项的每个站点都符合期望，记 PASS；任一站点不符，记该项 FAIL。
- 全部 PASS → 双容器分区预演支持 ADR-0008 的对账语义；任一 FAIL → 先判断是实现、编排还是期望错，写下理由后再改，不得只改期望。
- 原始快照、编排日志与失败全部保留在 `raw/`。

## 5. 不覆盖的内容（局限）

- 两个容器共享宿主机内核与时钟，**不覆盖时钟漂移与偏差**；
- `docker network disconnect` 是对称分区，**不覆盖非对称分区、丢包、乱序与高延迟**；
- 节点不持久化（未接入 ADR-0003 的追加日志），**不覆盖崩溃重启**；
- 无认证与加密（ADR-0008 §3.3 对生产传输的要求未实现）；
- 单台宿主机，不是两台物理节点，也不经过真实路由器或广域网。
