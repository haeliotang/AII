- 依据：[开发文档 M10](../../docs/DEVELOPMENT.zh-CN.md) · [SAP §4/§6](../../specifications/state-action-protocol.zh-CN.md) · [ADR-0007](../../docs/adr/0007-executor-idempotency-degradation.zh-CN.md)

## 1. 问题

> **H3（有界执行）**：在规定的故障模型下，有界执行不会产生**未登记的重复物理动作**，状态可对账；人工接管与安全降级在故障中仍有效。

## 2. 测试环境与限制

- **当前为模拟执行端**（`crates/poie-exec::sim`），非物理试验台。M10 退出条件要求物理试验台与人工安全演练；本模拟实验只作为库级预演，**不替代**物理 H3。
- 执行端声明支持幂等；另测"不支持幂等"时执行门拒绝派发（ADR-0007）。

## 3. 场景（14 个，先于运行固定）

故障模型（7 种故障 × 两种动作 `replace-sleeve-p1`、`turn-sleeve-p1` = 14 个场景）：

| 编号 | 故障 | 期望 |
| --- | --- | --- |
| F0 | 无故障 | 1 次物理动作，ACK 正常，verified |
| F1 | ACK 丢失 | 1 次物理动作；状态 `outcome_unknown`；不自动重试 |
| F2 | 执行端崩溃（执行后） | 1 次物理动作；`outcome_unknown`；不重试 |
| F3 | 重复投递（执行端内部） | 2 次物理动作；重复被**登记**，不隐藏 |
| F4 | 网络断连 | 0 次派发；`Fallback`；恢复后可重新授权 |
| F5 | 人工接管 | 0 次派发；记录 `RecordedOnly`；接管期间所有动作如此 |
| F6 | 运行时降级 | 0 次派发；`Fallback`；现场控制接管 |

每个场景记录：逻辑动作数、物理动作数、未登记重复数、SAP 状态、对账结果、接管/降级演练结果。

## 4. 指标与判定

- **主指标**：未登记的重复物理动作数 = 0（F3 的 1 次重复必须被登记，属于"已登记"）。
- 次指标：状态对账成功（`outcome_unknown` 的显式记录）、Fallback/RecordedOnly 计数、违反"无幂等不得派发"的次数 = 0。
- 判定：若所有场景未登记重复 = 0，且 F3 的物理重复被正确登记，则 H3 模拟部分被支持；否则失败并修复。
- 所有运行（含失败）都写入原始输出；不报告均值代替分布。

## 5. 公平性与复现

- 固定代码提交与执行顺序；无随机源；场景表固定在本文件；
- 运行器写入 `raw/sim-<date>.txt` 与 `REPORT.sim.md`；
- 模拟结果明确标注"simulated, not physical"。

## 6. 局限

- 模拟执行端不能证明真实 PLC/机器人行为；
- 真实断电/断网、物理急停与安全评审未覆盖（M10 退出条件）；
- 真实执行端的幂等实现尚未验证（M9.2 适配器）。
