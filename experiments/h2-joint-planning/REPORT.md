## 1. 方法与场景

| 方法 | 说明 |
| --- | --- |
| A 联合规划 | 结构候选 + 调度 + 失败恢复（M8.1）+ 新观测重规划（M8.2），动作经 SAP 校验 |
| B1 任务优先级 | 固定顺序，仅结构阻断时修复，忽略截止 |
| B2 安全库存规则 | B1 + 修复/路线资源安全阈值 |
| B3 短期优化 | 每次选择最早完成目标，忽略截止 |

场景：24 个（16 开发 + 8 留出），由固定种子生成；扰动为泵失效时刻、母线失效时刻、初始电池能量、补给中断时刻（见 PREREG §3）。所有方法使用**完全相同的扰动轨迹、预算与 SAP 校验路径**；每个计划都经 `validate_plan_through_sap`。

运行命令：

```bash
cargo run -p poie-h2-joint-planning -- --dev --write experiments/h2-joint-planning
cargo run -p poie-h2-joint-planning -- --holdout --write experiments/h2-joint-planning
```

原始输出：[`raw/dev-raw.txt`](raw/dev-raw.txt)、[`raw/holdout-raw.txt`](raw/holdout-raw.txt)；自动汇总：[`dev-report.md`](dev-report.md)、[`holdout-report.md`](holdout-report.md)。

## 3. 消融观察（开发集）

- **短期时域（只规划 1 h）明显更差**：4/16 vs 14/16。长期时域是有效组件。
- 无重规划 / 无截止 / 能力盲与完整方法持平；能力盲仍使用结构求解，是弱消融，不能单独证明能力依赖的价值。
- 这些消融不改变主判定。

## 4. 方法自身错误与失败

- SAP 校验失败：**0**（开发 16×8 + 留出 8×4 全部通过）。
- 运行失败/超时/不可行：无（所有运行完整输出）。
- 观察到的"成功但最终计划含未达成原因"（如 h2-18）来自成功判据使用截止时刻的服务可用性，而最终计划仍报告 deadline missed；该判据在预登记中固定，未在留出集后修改。

## 5. 解释与局限

1. **基线并不弱**：B1–B3 都使用同一结构求解器，能力/资源推理已共享；本实验中真正的差异只可能来自时间/重规划，而当前扰动时序下这些差异没有改变结果。
2. **场景区分度低**：泵失效集中在 4 h 截止附近的少数几种模式；母线失效多数在截止之后，未真正进入比较。
3. **贪心规划器**（ADR-0006）没有最优性；但其未劣于基线，说明瓶颈不在规划器强度。
4. **合成、未校准**：时间/成本参数为假设，无外部校准数据；样本 24（留出 8），作者相同，外部配额（M3.3）仍为 0；统计功效有限。
5. 结论只适用于本模型与扰动集合；不支持"联合规划普遍优于规则"的强主张。

## 8. 2026-11-01 补充：按修订后的 VEC 复核

VEC 2026-11-01 修订新增了终端条件、可检查的非预知性、唯一主要指标与阈值等要求。重跑后自动汇总（[`dev-report.md`](dev-report.md)、[`holdout-report.md`](holdout-report.md)）与原始输出新增三列，原有列不变：

- **非预知检查**：每次决策只使用不晚于决策时刻的事件（`max_lookahead_s` ≤ 0），四种方法、全部 24 场景通过；同一方法的同一实例在全部场景上运行。留出集共 15 次决策/方法，开发集共 23 次（无重规划消融为 16 次）。
- **终端状态**：PREREG 没有终端约束。A 与三种基线在部分场景中期末储能为 **0 kWh**（初始 0.5 kWh 全部用于更换轴套），即在时域末端把电池用尽；这正是修订后 §2.1 要求报告终端状态的情形。由于没有预登记终端约束，它不参与本次判定，但"成功"不应被读作期末仍有余量。
- **主要指标**：§5 判定只用截止成功率与 15 pp 阈值，符合"唯一主要指标 + 预登记阈值"；PREREG §4 中的第二个"主指标"（服务维持时长）从未报告，按修订后的契约只能作探索性指标。
- **留出集**：已在 2026-10-31 首次运行并查看，本次重跑只为可复现与补充报告列，不构成新的留出评估。
