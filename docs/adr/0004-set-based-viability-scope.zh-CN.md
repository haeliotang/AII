# ADR-0004：集合式可行性方法的范围（M6.6 评估）

- 状态：提议（M6.6 评估完成，待 M6 退出复核确认）
- 日期：2026-10-31
- 决策者：项目维护者（AI 代理起草，人类可推翻）
- 相关：[VEC §3.2](../../specifications/viability-expansion.zh-CN.md)、[M6.6](../DEVELOPMENT.zh-CN.md)、[ADR-0003](0003-append-only-local-log.zh-CN.md)
- 取代/被取代：无

## 1. 背景

VEC §3.2 允许四种方法：`sampled`、`enumerated`、`set_based`、`certificate`。M6.1–M6.5 已实现前两种及结构层恢复路径桥接。M6.6 要求评估：在小规模 Base-01 上做**集合可达**或**区间界**是否可行，以及是否应在 M6 内实现。

VEC §1.3 与 §3.2 同时规定：只有穷举或集合方法覆盖整个 W 时，才能给出"在模型与 W 内成立"的强表述；保守近似必须说明保守方向。

## 2. 评估

### 2.1 状态空间

- Base-01 v0.2：9 个资产 × 4 个状态（available/degraded/failed/unknown）≈ 2.6×10⁵ 种离散组合；库存与能量是连续量（青铜 3 kg、轴套 1、能量 1–41 kWh 等）。
- 扰动包含固定轨迹（6 h/12 h/16 h 故障、8 h/10 h 补给变化）与状态相关故障率；策略非预知（VEC §2.1）。
- 时域为事件驱动，维修动作会改变后续状态，状态图不是简单的单调转移。

### 2.2 区间/抽象方法

- **可行部分**：库存与能量在给定事件序列下的上下界较直接（单调增减 + 补给/消耗上界）；容量与并发约束可做区间检查；这能给"资源不会耗尽"的保守界。
- **困难部分**：服务可用性取决于"资产状态—能力—路线"的非单调组合（例如母线故障使机器人—充电桩循环阻断，恢复动作又依赖同一批资产）。对状态集合做抽象后，恢复动作与替代路线会使不动点计算复杂化；保守方向需要精确定义并验证。
- **证书方法**：结构层 `blocked` 已能作为"模型内不可行"的依据（能力图根因、可检查的阻断原因）；但**时域不可行**（如"在截止前不可能修复"）目前只有调度/资源检查的反例，缺少可独立检查的不可行证书（例如资源下界 + 截止约束的证明）。

### 2.3 成本与风险

- 完整集合可达需要新的抽象解释器与精化循环，工作量与 M6 其余工作相当，超出本轮范围。
- 采样/枚举在 20 个时间版场景上已能给出"被测/有限 W"结论，足以支撑 M6 退出条件；过早实现集合方法会给出未经校准的强结论，违背 VEC §1.3。
- 现有报告守卫已能阻止把 `held_on_tested` 表述为安全/鲁棒；集合方法若实现，必须新增独立的表述校验（保守方向声明）。

## 3. 决定

1. **M6 不实现 `set_based` 与 `certificate` 方法**；M6 的报告与结论只使用 `sampled` / `enumerated` 的最强表述。
2. 将"区间抽象最小原型"列为独立探索项，触发条件：需要"在模型与 W 内成立"的强结论、或外部评审提出该要求。
3. 最小原型的验收要求（先在 ADR 中固定，避免事后放宽）：
   - 明确声明保守方向（下界/上界分别对应"成立"还是"不确定"）；
   - 与 `sampled` 反例交叉验证：抽样找到的反例必须被集合方法标记为"不确定"或被排除；
   - 对 Base-01 v0.2 的 20 个场景给出与 `enumerated` 一致的结论（在重叠部分）；
   - 新增表述校验，禁止未经证明的"模型内成立"声明。
4. 实现前必须新增 ADR 或修订本 ADR（状态改为"已接受"）；M8 之后重新评估。

## 4. 后果

- VEC §3.2 的 `set_based`/`certificate` 在 M6 报告中标注"未实现/未使用"；人读报告不得暗示强于被测范围的结论。
- 结构层的 `blocked` 仍可作为不可行依据（VEC §3.3），时域不可行只报告反例与未决（timeout），不冒充证书。
- 集合方法若进入路线图，需同步更新 VEC 的退出条件与 M6/M8 计划。
