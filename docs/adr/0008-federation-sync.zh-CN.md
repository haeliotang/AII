# ADR-0008：跨站同步与重连对账（M12.1）

- 状态：提议（M12 开发中，待 M12 退出复核确认）
- 日期：2026-10-31
- 决策者：项目维护者（AI 代理起草，人类可推翻）
- 相关：[开发文档 M12](../DEVELOPMENT.zh-CN.md)、[SAP §6](../specifications/state-action-protocol.zh-CN.md)、[ADR-0003](0003-append-only-local-log.zh-CN.md)
- 取代/被取代：无

## 1. 背景

M12 要求多个独立场址协作、网络分区不破坏本地权责。需要决定：(a) 日志交换与因果排序的机制；(b) 传输技术；(c) 重连对账策略，尤其不得使用"最后写入胜出"覆盖命令与预留。

## 2. 评估

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 进程内模拟交换（M12 库级，选定） | 无网络依赖、可精确测试分区/重复/冲突；确定性 | 不能证明真实网络行为 |
| HTTP/gRPC 拉取 | 简单、易审计 | 需认证/加密/重试/时钟处理；真实多节点测试成本高 |
| 消息总线（MQTT/NATS 等） | 实时、可扩展 | 运维与安全边界复杂；需要 ADR 与部署 |
| 文件/rsync 批次交换 | 最简、断网友好 | 延迟高；冲突窗口大 |

关键事实：命令与预留的安全要求不允许最后写入胜出；HLC 已在 SAP 中用于因果排序，但真实多节点的时钟偏差、认证与重放仍需要真实环境验证（M12.6）。

## 3. 决定

1. **M12 库级使用进程内模拟日志交换**：每个场址持有按 `RecordId` 去重的记录集；重连时双向合并，缺失记录按 `(site, seq)` 插入，合并视图按 HLC（physical, logical）→ site → seq 因果排序；收到远端 HLC 时本地时钟 `observe` 前进。
2. **对账不做最后写入胜出**：重复幂等键、双派发、超额预留、双重所有权（含时钟偏差界）全部生成**冲突报告**，由人工解决；预留与租约不因冲突被静默丢弃。
3. **生产传输推迟**：HTTP/gRPC、消息总线或文件交换的选择留待真实多站点条件具备时另写 ADR；届时必须满足：
   - 双向认证与传输加密；
   - 至少一次投递 + 幂等合并（按 `RecordId` 去重）；
   - 有界时钟偏差与 HLC 合并；
   - 分区/重连/重放的自动化测试；
   - 与 M12.6 的真实多节点复测结合。
4. **Base-02 场景**（共享库存与运输能力）在 M12.5 实现，使用同一交换/对账接口。

## 4. 后果

- M12 库级可验证分区、重复投递、冲突与重连行为，但不能宣称真实网络或真实多站点已验证；
- 冲突处理需要操作者流程；报告必须列出全部冲突与未解决项；
- 生产传输实现前，多站点部署不进入"已验证"声明。
