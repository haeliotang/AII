# ADR-0005：水处理过程模型的选择（M7.2）

- 状态：提议（M7 开发中，待 M7 退出复核确认）
- 日期：2026-10-31
- 决策者：项目维护者（AI 代理起草，人类可推翻）
- 相关：[开发文档 M7](../DEVELOPMENT.zh-CN.md)、[python/poie_models](../../python/poie_models/README.md)、[VEC §9](../../specifications/viability-expansion.zh-CN.md)
- 取代/被取代：无

## 1. 背景

M7 需要让 Rust 核心以受控方式调用过程模型，优先水处理（原水泵 + 过滤单元），要求声明适用范围、可复现、失败可分类，并且不把模型输出直接当成事实。候选包括 IDAES 等专业过程建模框架。

## 2. 评估

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| IDAES | 机理完整、社区支持、可扩展到动态 | 依赖重（Pyomo/IPOPT 等）、安装与 CI 成本高、版本漂移、当前无校准数据 |
| 纯 Python 简化模型（选定） | 无外部依赖、协议/失败路径可精确测试、范围可声明、易于替换 | 物理保真度低、只能用于协议与演示 |
| 直接调用商业仿真器 | 精度可能高 | 许可、可复现性、黑盒 |

关键事实：当前**没有任何校准数据**（见 DATA.zh-CN.md），高保真模型也不能给出可信的定量结论；M7 的退出条件是"服务水平由过程模型计算、失败可分类、适用范围可见"，而不是精度。

## 3. 决定

1. **M7.2 使用纯 Python 简化模型** `water.py`（`water-treatment` v0.1.0），声明输入范围、守恒关系与 `synthetic = true`；
2. 桥接协议（M7.1）与校验（M7.3）保持模型无关：未来 IDAES 模型只需实现同一 JSON-line 协议与声明；
3. IDAES 的引入条件：获得至少一个可引用的校准/中试数据集，且简化模型不足以支撑 H2 实验；引入时需新增 ADR 或修订本 ADR；
4. 任何报告在使用该模型时必须显示 `synthetic` 与适用范围，超出范围返回 `out_of_validity`，不得外推。

## 4. 后果

- M7 的定量结果只作为"接口与失败路径已打通"的证据，不作为物理结论；
- 报告与 README 均标注模型未校准；
- 若后续引入 IDAES，协议、Rust 客户端与校验无需改变，只需新模型实现与数据。
