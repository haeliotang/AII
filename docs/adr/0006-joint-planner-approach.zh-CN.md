# ADR-0006：联合规划的求解器选择（M8.1）

- 状态：提议（M8 开发中，待 M8 退出复核确认）
- 日期：2026-10-31
- 决策者：项目维护者（AI 代理起草，人类可推翻）
- 相关：[开发文档 M8](../DEVELOPMENT.zh-CN.md)、[VEC §8](../../specifications/viability-expansion.zh-CN.md)、[ADR-0004](0004-set-based-viability-scope.zh-CN.md)
- 取代/被取代：无

## 1. 背景

M8.1 需要从结构候选与时间约束出发，产出生产—维护—恢复的联合动作序列（`proposed`），附前提、预算、有效期，并且所有动作必须经过 SAP 校验路径。候选方案包括 MILP/CP（Python 侧）与确定性启发式。

## 2. 评估

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| MILP/CP（Python） | 可优化完工时间/成本/并行调度，支持全局约束 | 引入求解器依赖与许可；数值容差导致结果不总是可逐位重放；建模成本高；当前无校准成本数据，目标函数缺乏依据 |
| 确定性启发式（选定） | 无外部依赖、可逐位重放、与 SAP 动作一一对应、H2 基线公平 | 贪心、非全局最优、并行调度能力有限 |
| 手工规则 | 最简单 | 无法表达能力依赖与恢复链，不适合作为方法 A |

关键约束：H2 需要**公平基线**与可复现实验；如果方法 A 使用强优化器而基线是简单规则，差异可能来自求解器而非模型。M8 的当前阶段更关心"动作序列能否被 SAP 校验、能否表达生产—维护—恢复的耦合"，而非最优性。

## 3. 决定

1. M8.1 实现**确定性贪心规划器**（`crates/poie-plan`）：按优先级求解结构目标 → 调度路线 → 遇到失败资产时尝试恢复并重解（有界轮次）；输出带前提/预算/有效期的 `proposed` 动作；
2. 规划器输出必须经 `validate_plan_through_sap`（proposed → validated → authorized + 六项派发前检查），不存在绕过授权的接口；
3. MILP/CP 推迟，触发条件（先写入 ADR，避免事后放宽）：
   - H2 显示贪心规划在 ≥20% 的可行场景中明显劣于基线或错过可行计划；
   - 或场景规模超出当前贪心可处理范围（动作数/并行度增长）；
   - 引入时需新 ADR，说明目标函数、求解器版本、容差与可重放策略，并保证基线公平。
4. 规划器不宣称最优；H2 报告只比较"相对基线的表现"并披露规划器的贪心性质。

## 4. 后果

- M8.1 的动作序列可用于 SAP 校验与 H2 实验，但不保证最优；
- 规划质量由 H2 相对基线衡量，负结果同等报告；
- 若后续采用 MILP/CP，动作接口与 SAP 校验路径不变，仅替换规划器内部。
